# ORGANISM M1 — сохранение истории и границы опыта

**Статус:** первый безопасный срез; M1 не завершён до сборки и сквозного теста на Android.  
**Рабочая ветка:** `feature/m1-chat-history-preservation`  
**PR:** https://github.com/alexbotleh-oss/organism/pull/6  
**Основа:** `main` на commit `e203d9ef48af7d2dd3325f1e9386182cda6943c8`.

## Почему этот этап нужен

ORGANISM создаётся для непрерывности работы между чатами и моделями. Поэтому импорт истории должен сохранять не только текст, но и происхождение, порядок, структуру ветвлений и границу между исходными данными и интерпретацией.

## Что изменено в этом срезе

1. В ChatGPT ZIP исходный `conversations.json` сохраняется как RAW-источник.
2. Каждая беседа получает дочернюю запись источника с `parent_source_id` и `conversation_id`. Полный JSON не копируется в каждую дочернюю запись.
3. Импорт строит детерминированный обход узлов по `parent` / `children`; не полагается на произвольный порядок итерации JSON-объекта.
4. В контексте сохраняются node ID, parent/children, current node, роль, автор (если есть), timestamp, channel и узлы без сообщения.
5. Отсоединённые или циклические узлы не выбрасываются: они добавляются детерминированно после доступных корневых ветвей.
6. Сообщения импортированной беседы сохраняются отдельными поисковыми объектами памяти с node ID и provenance. Длинная беседа больше не сводится к одному объекту, который при передаче контекста обрезался бы в начале. Context Engine передаёт до 1400 символов выбранного объекта.
7. Context Snapshot включает последние 12 сообщений живого диалога проекта в хронологическом порядке. Пользовательские реплики помечаются как `USER_STATED`, ответы модели — `MODEL_OUTPUT_NOT_VERIFIED`, ошибки — `ERROR_EVENT`. Это восстанавливает непосредственную историю в запросе, но пока не изолирует отдельные session ID.
8. Ответ модели больше не записывается автоматически как переиспользуемый опыт. Нейтральные автоматические взаимодействия исключены из выдачи опыта в Context Handoff.
9. Удалён эвристический разбор произвольного текста на «ингредиенты / шаги / советы / БЖУ», который мог создавать ложные производные записи.
10. Добавлены документация и workflow сборки Android debug APK.

## Что не заявлено как готовое

- Полноценный семантический извлекатель `EVENT → ACTION → RESULT → VERIFICATION` пока не реализован.
- Сборка workflow последнего commit должна быть подтверждена CI; реальное устройство не проверено.
- Не проверены большие ChatGPT ZIP, импорт после перезапуска, восстановление backup и повторный импорт без дубликатов.
- Недавний диалог пока выбирается по проекту, а не по отдельной сессии; перед production нужно добавить явную связь event ↔ session и тест на разделение нескольких диалогов.
- Порядок parent/children — детерминированное восстановление графа. Оно не доказывает причинность и не делает найденные утверждения фактами.
- В старой базе могут оставаться ранее автоматически созданные записи опыта типа `NEUTRAL`; они исключены из выбора опыта для контекста, но не удаляются.
- История сообщений сохраняет структурные ссылки на источник, но точные диапазоны символов исходного JSON ещё не записываются как отдельные source spans.

## CI findings / experience candidates

- **Наблюдавшаяся ошибка:** первый Android build дошёл до Java-компиляции и завершился ошибкой: используемый Android `org.json.JSONObject` не предоставляет `valueToString(Object)`.
- **Исправление внесено:** нестроковые части JSON теперь сериализуются через `String.valueOf(part)`; строки добавляются напрямую.
- **Статус:** исправление считается `NOT_VERIFIED`, пока CI не соберёт последний commit успешно. Не сообщать, что оно подтверждено, до нового результата.
- **Урок процесса:** проверять именно Android target на раннем этапе; методы другой реализации JSON нельзя считать доступными в Android `org.json`.

## Следующий этап — M1 semantic extraction

Не переписывая RAW:

1. Разобрать структурированные сообщения в события с точными ссылками на источник и message/node ID.
2. Извлекать только то, что явно поддержано исходными фрагментами: `EVENT`, `ACTION`, `RESULT`, `VERIFICATION`, `FAILURE`, `CAUSE_SUSPECTED`, `CAUSE_CONFIRMED`, `DECISION`.
3. Отдельно различать `FACT`, `EXPERIENCE_CANDIDATE`, `HYPOTHESIS` и `NOT_VERIFIED`.
4. Кандидат опыта строить из цепочки «условия → действие → наблюдаемый результат → проверка» либо «попытка → ошибка → подтверждённая/предполагаемая причина → исправление → проверка».
5. Не повышать статус на основании повторения модели, согласия нескольких моделей, благодарности или одного лишь ответа ИИ.
6. Хранить неразобранные фрагменты и пробелы покрытия; не придумывать недостающие звенья.
7. Прогнать длинную реальную историю ORGANISM как первый регрессионный материал и сравнить извлечённые события с известными решениями, ошибками и подтверждёнными исправлениями.

## Регрессионные проверки перед объединением

- RAW checksum соответствует сохранённому исходному тексту.
- Все node IDs присутствуют; parent/children и current node не теряются.
- Ветви и узлы без message не исчезают.
- JSON с изменённым порядком ключей даёт одинаковый детерминированный результат.
- Данные из импортированной истории остаются кандидатами, пока не пройдена отдельная проверка.
- Нейтральный ответ модели не попадает в reusable experience.
- Сборка APK проходит; импорт, чат, память и восстановление проверяются на Android.
