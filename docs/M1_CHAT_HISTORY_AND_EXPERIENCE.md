# ORGANISM M1 — сохранение истории и границы опыта

**Статус:** первый безопасный срез; не считать M1 завершённым до сборки и сквозного теста на Android.  
**Рабочая ветка:** `feature/m1-chat-history-preservation`  
**PR:** https://github.com/alexbotleh-oss/organism/pull/6  
**Основа:** текущая `main` на commit `e203d9ef48af7d2dd3325f1e9386182cda6943c8`.

## Почему этот этап нужен

ORGANISM создаётся для непрерывности работы между чатами и моделями. Поэтому импорт истории должен сохранять не только текст, но и происхождение, порядок, структуру ветвлений и границу между исходными данными и интерпретацией.

## Что изменено в этом срезе

1. В ChatGPT ZIP исходный `conversations.json` сохраняется как RAW-источник.
2. Каждая беседа получает дочернюю запись источника с `parent_source_id` и `conversation_id`. Полный JSON не копируется в каждую дочернюю запись.
3. Импорт строит детерминированный обход узлов по `parent` / `children`; не полагается на порядок итерации JSON-объекта.
4. В записи контекста сохраняются node ID, parent/children, current node, роль, автор (если есть), timestamp, channel и узлы без сообщения.
5. Отсоединённые или циклические узлы не выбрасываются: они добавляются детерминированно после доступных корневых ветвей.
6. Содержимое импортированной истории и ответы модели не превращаются автоматически в подтверждённый опыт.
7. Удалён прежний эвристический разбор произвольного текста на «ингредиенты / шаги / советы / БЖУ». Такой разбор не подходит для общей истории чатов и мог создавать ложные производные записи.
8. Добавлен отдельный workflow для сборки Android debug APK.

## Что не заявлено как готовое

- Полноценный семантический извлекатель `EVENT → ACTION → RESULT → VERIFICATION` пока не реализован.
- Сборка workflow ещё не подтверждена результатом CI; реальное устройство не проверено.
- Не проверены большие ChatGPT ZIP, импорт после перезапуска, восстановление backup и повторный импорт без дубликатов.\n- Недавний диалог пока выбирается по проекту, а не по отдельной сессии; перед production нужно добавить явную связь event ↔ session и тест на разделение нескольких диалогов.
- Порядок parent/children — детерминированное восстановление графа. Оно не доказывает причинность и не делает найденные утверждения фактами.
- В старой базе могут оставаться ранее автоматически созданные записи опыта типа `NEUTRAL`; они исключены из выбора опыта для контекста, но не удаляются.
- Ветка не объединена в `main`. PR #4 и #5 не сливались и не изменялись этим этапом.

## Следующий этап — M1 semantic extraction

Не переписывая RAW:

1. Разобрать структурированные сообщения в события с точными ссылками на источник и message/node ID.
2. Извлекать только то, что явно поддержано исходными фрагментами: `EVENT`, `ACTION`, `RESULT`, `VERIFICATION`, `FAILURE`, `CAUSE_SUSPECTED`, `CAUSE_CONFIRMED`, `DECISION`.
3. Отдельно различать `FACT`, `EXPERIENCE_CANDIDATE`, `HYPOTHESIS` и `NOT_VERIFIED`.
4. Кандидат опыта строить из цепочки «условия → действие → наблюдаемый результат → проверка» либо «попытка → ошибка → подтверждённая/предполагаемая причина → исправление → проверка».
5. Не повышать статус на основании повторения модели, согласия нескольких моделей, благодарности или одного лишь ответа ИИ.
6. Хранить неразобранные фрагменты и пробелы покрытия; не придумывать недостающие звенья.
7. Прогнать длинную реальную историю ORGANISM как первый регрессионный материал и сравнить извлечённые события с известными решениями, ошибками и подтверждёнными исправлениями.

## Регрессионные проверки перед объединением

- RAW checksum сохраняется и совпадает с импортированным текстом.
- Все node IDs присутствуют; parent/children и current node не теряются.
- Ветви и узлы без message не исчезают.
- JSON с изменённым порядком ключей даёт одинаковый детерминированный результат.
- Данные из импортированной истории остаются кандидатами, пока не пройдена отдельная проверка.
- Нейтральный ответ модели не попадает в reusable experience.
- Сборка APK проходит; импорт, чат, память и восстановление проверяются на Android.
