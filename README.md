# ORGANISM — мобильный прототип и система непрерывности

ORGANISM — проект «история → знания → опыт → применение». Его задача — сохранять рабочий контекст, происхождение данных, решения, результаты и проверенный опыт между чатами и моделями.

> **Текущий статус:** экспериментальный проект в активной разработке. Наличие Android-кода, SQLite и отдельных тестов не означает, что весь цикл памяти и опыта уже работает сквозным образом. Сборка и работа на реальном устройстве должны подтверждаться отдельно.

## Что находится в репозитории

### 1. Native Android app — основной мобильный контур

Путь: `app/`  
Язык: Java, Android SDK, SQLite.

Существующие компоненты:
- мобильная оболочка с экранами чата, памяти, импорта, базы и настроек;
- локальная SQLite-база с проектами, состояниями, задачами, источниками, событиями, памятью, отношениями и опытом;
- Context Engine для формирования Context Snapshot перед запросом модели;
- Reflex Engine для предварительных защитных проверок;
- ChatGPT connection flow;
- импорт TXT/MD/PDF/URL и ChatGPT ZIP;
- экспорт резервной копии базы.

**Ограничения:** это не законченная production-система. Семантическое извлечение опыта из истории, проверка реального результата действия, дедупликация повторных импортов, миграции/восстановление на устройстве и сквозная Android-проверка требуют дальнейшей работы. Ответ модели сам по себе не является проверенным опытом.

### 2. PWA prototype

Путь: `web/`

Это отдельный ранний HTML/PWA-прототип с локальным хранилищем браузера. Его данные и поведение нельзя автоматически считать синхронизированными с нативной Android SQLite-базой.

### 3. Локальный Python bridge

Файлы: `organism_server.py`, `requirements.txt`

Экспериментальный локальный мост к модели. Запуск:

```bash
python -m pip install -r requirements.txt
python organism_server.py
```

Затем открыть `http://127.0.0.1:1455/`.

Bridge — отдельный экспериментальный контур, а не доказательство завершённой интеграции с Android-приложением. OAuth-учётные данные не должны попадать в Git. Не открывайте локальный сервер в LAN/интернет без отдельной аутентификации и модели разрешений.

## Сборка Android

Требуются Android Studio / Android SDK, JDK 17 и Gradle 8.9. В репозитории нет Gradle Wrapper, поэтому можно открыть проект в Android Studio и собрать конфигурацию `:app:assembleDebug`, либо при установленном Gradle выполнить:

```bash
gradle --no-daemon :app:assembleDebug
```

Workflow сборки добавлен в ветке M1; до появления результата CI сборку нельзя считать подтверждённой.

## Основной архитектурный принцип

```text
RAW
→ PROVENANCE
→ EXTRACTION
→ AUDIT
→ MEMORY / LOSS-COVERAGE MAP
→ CONTEXT SNAPSHOT / MEMORY HANDOFF
→ MODEL
→ APPLICATION OUTCOME
→ VERIFICATION
→ EXPERIENCE CANDIDATE
→ AUDIT
→ FUTURE APPLICATION
```

- RAW не заменяется пересказом.
- Каждый производный объект должен иметь ссылку на источник и исходный фрагмент.
- Факт, утверждение модели, гипотеза, кандидат опыта и проверенный результат — разные статусы.
- Согласие нескольких моделей и повторение одного вывода не являются независимой проверкой.
- Опыт должен содержать условия, действие, наблюдаемый результат и способ проверки; отрицательный опыт также сохраняется.
- Неполная история не должна молча превращаться в полную. Неизвестное остаётся неизвестным.
- Защитные правила должны предотвращать опасные изменения, но не запускать бесконечные циклы проверок.

## Главный сквозной тест

Реальная длинная история → импорт без потери RAW/узлов/ветвей → извлечение событий с provenance → кандидаты опыта с явными статусами → новый диалог → Context Snapshot → модель → наблюдаемый результат → отдельная проверка → опыт, пригодный к условному повторному применению.

Проверка считается успешной только после подтверждения данных и поведения на реальном Android-устройстве, включая перезапуск и восстановление из резервной копии.
